# 과거값보완 — 점검데이터 빈칸을 「과거 기록과의 비교」로 채우기

> `review/과거값보완.js` · v1.0 (2026-11-23) · **기존 코드를 한 줄도 고치지 않는 독립 파일**

---

## 1. 무엇을 하는가

`점검기록표_YYYYMM` 시트에서 **빈칸만** 골라, **같은 발전소의 과거 기록과 비교해서**
가장 그럴듯한 값과 그 근거를 함께 보여 줍니다. 사람이 확인하고 고른 칸만 씁니다.

- 이미 값이 있는 칸은 **절대** 건드리지 않습니다.
- 수식이 걸린 열은 통째로 건너뜁니다.
- 채운 칸마다 **무엇을 · 왜 · 어디서** 가져왔는지 남깁니다.
- 한 번 실행한 것을 **통째로 되돌릴 수** 있습니다.

---

## 2. 설치 (3분)

1. 점검시스템 Apps Script 편집기 → 파일 목록 **[+]** → **스크립트**
2. 이름을 `과거값보완` 으로
3. `review/과거값보완.js` **전체**를 붙여넣고 저장
4. 함수 목록에서 **`과거값보완_설치`** 를 한 번 실행 → 권한 승인
5. 시트를 새로 고치면 맨 오른쪽에 **`🧹 점검데이터 보완`** 메뉴가 생깁니다

> ⚠️ `onOpen` 은 **재정의하지 않습니다.** 설치 함수가 `과거값보완_onOpen` 이라는
> 전용 트리거를 따로 만듭니다. 기존 메뉴는 그대로 남습니다.
> (같은 이름을 두 번 정의하면 스크립트 전체가 죽는 사고가 있었기 때문입니다 — 2026-08-14)

### 시트 ID 지정

이 도구는 아래 순서로 스프레드시트를 찾습니다.

| 순서 | 위치 |
|---|---|
| 1 | 스크립트 속성 `PASTFILL_DATA_SS_ID` / `PASTFILL_MASTER_SS_ID` |
| 2 | 파일 안 `PFILL.FALLBACK` (비어 있음) |
| 3 | 기존 `CONFIG.DATA_SS_ID` / `CONFIG.MASTER_SS_ID` (있으면 자동으로 씀) |

기존 프로젝트에 넣으면 **3번으로 자동 연결**되므로 보통 설정할 것이 없습니다.
대장(`수용가관리대장`)은 없어도 동작합니다 — 점검회차 계산만 조금 약해집니다.

---

## 3. 쓰는 법

메뉴 → `🧹 점검데이터 보완` → **🔍 과거값 비교 · 빈칸 찾기**

1. **연월** 고르기 (그 달 탭이 있는 것만 나옵니다)
2. 필요하면 **발전소** 하나만 고르기
3. **🔍 비교 · 빈칸 찾기** — 이 단계는 **읽기만** 합니다
4. 표에서 채울 칸을 고릅니다 (**전체 선택 / 선택 해제** 가능)
5. **✅ 선택한 칸 채우기**

### 화면에 보이는 것

| 표시 | 뜻 |
|---|---|
| `A` (초록) | 같은 달 안에서 이미 나온 값 — 가장 믿을 만함 |
| `B` (노랑) | 그 발전소의 최근 이력 (최근 6회 중앙값) |
| `C` (빨강) | 같은 달 **다른 발전소**의 중앙값 — 참고용, 기본 꺼짐 |
| 신뢰도 높음/보통/참고 | 표본 수와 흩어진 정도(변동계수)로 판정 |
| **출처** 칸 | 「이 발전소 최근 4회 중앙값 (202605~202609)」 처럼 근거를 그대로 적습니다 |

## 4. 값을 정하는 순서

신뢰도가 높은 것부터 봅니다. 앞의 것이 없으면 다음으로 넘어갑니다.

| 순위 | 열 종류 | 방법 | 군 |
|---|---|---|---|
| 1 | `점검회차현황` `완료여부` `M_ROOM_TEMP` | 같은 행의 다른 값으로 **계산** | A |
| 2 | `전월송전전력` | 같은 달 다른 회차 값 → 없으면 지난달 마지막 회차의 「현재송전전력」 | A |
| 3 | 측정값 `M_` `R_` `vcb_` `tr_temp_` `No1~` | 그 발전소 **최근 6회 중앙값** | B |
| 4 | 판정값 `V_` | 그 발전소 과거 **최빈값** (2회 이상 일치할 때만) | B |
| 5 | `날씨` / `기온` / `점검시각` | 같은 달 과거의 최빈값 / 중앙값 (참고용) | B |
| 6 | 그 밖의 열 | 이력으로 숫자/글자를 가려 처리 | B·C |

### 복합값은 자리마다 따로

`"225/224/225 | 220/221/219"` 처럼 `/`(상) 와 `|`(묶음) 로 이어진 값은
**자리마다 중앙값**을 냅니다. 모양(묶음 수·조각 수)이 다르면 계산하지 않습니다 —
3상 값과 단상 값이 섞이면 엉뚱한 답이 되기 때문입니다.

### 중앙값의 소수 자릿수

표본의 소수 자릿수를 지킵니다. 표본이 **짝수**면 가운데 둘을 평균하므로 한 자리가 늘 수 있습니다.

```
12.1 · 12.4  →  12.25     (12.3 으로 깎지 않습니다 — 그러면 중앙값이 아니게 됩니다)
 3.1 ·  3.3  →   3.2
500  ·  520   →   510
```

## 5. 일부러 채우지 않는 것

| 열 | 왜 |
|---|---|
| `점검ID` `설비번호` `점검일자` `제출키` `기록일시` | 식별자 — 틀리면 행이 뒤섞입니다 |
| `점검자` `점검유형` `점검구분` | **누가·무엇으로 했는지**는 과거 값으로 채우면 거짓 기록이 됩니다 |
| `검토메모` `수정일시` `수정자` `사진폴더URL` `보고서URL` | 시스템 열 |
| `특이사항` `조치내용` `요청업체` `종합점검결과` `비고` `조치구분` | 빈칸이 정상인 자유기술 (필요하면 화면에서 「자유기술 열까지」 체크) |
| **수식이 걸린 열** | 수식을 지우면 계산이 깨집니다 |

> `완료여부` 는 `조치구분` 이 **비어 있으면 계산하지 않습니다.**
> 「미완료」 라고 단정하면 사실과 다를 수 있기 때문입니다.

## 6. 되돌리기

두 가지 방법이 있습니다.

- 메뉴 → **🕘 되돌리기 (최근 실행)** → 번호 선택
- 미리보기 창 → **🕘 되돌리기**

실행ID 하나를 통째로 되돌립니다. 열 이름으로 다시 찾아 쓰므로
**그 사이 열이 움직였어도** 제자리에 돌아갑니다.

## 10. 기존 코드와의 관계

- 기존 파일을 **한 줄도 고치지 않습니다.**
- 기존 전역 함수를 **부르지 않습니다** (`CONFIG` 변수만 읽기 전용으로 참조).
- 새 전역 이름은 전부 `pf…` / `PFILL` / `과거값보완_…` 로 시작합니다 — 충돌 0건 확인.
- 기존 `dataFillMissing`(한 열씩 4번 묻는 방식)과는 **별개**입니다. 그 기능은 그대로 있습니다.

### 기존 지침과 다른 점 (의도적)

CLAUDE.md §0-1 의 「판정값은 기본 O」 · 「`MISSED_ROUND_BLANK_` 를 지어내지 않는다」 같은
규칙은 이 도구에 적용하지 않았습니다. 이 도구는 **과거 기록에서 근거를 찾아** 값을 제안하고,
근거가 없으면 `빈칸` 으로 남깁니다. 지어내지 않는 원칙은 그대로입니다.
